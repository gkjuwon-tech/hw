### [WARNING] `BOM-COUNTERFEIT-RISK` — C155591 (TLV1117LV33DCYR (TI, SOT-223)) has documented counterfeit-risk on LCSC

**Refs:** `U5`

If the part is a relabelled HT73xx clone, Vdo at 500 mA WiFi peak climbs to ~1.4 V leaving Vout = 5 - 1.4 = 3.6 V minus diode drops; OK on paper but thermal shutdown is the real risk.

### [WARNING] `BOM-COUNTERFEIT-RISK` — C5183 (CD74HC4067SM96 (TI marking; LCSC often ships HGSemi or 3PEAK clone)) has documented counterfeit-risk on LCSC

**Refs:** `U2`, `U3`

*** Top measurement-quality risk ***. The ADC divider math assumes R_mux_on = 80 ohm in the schematic. Real R_on at 3V3 on a genuine TI is already 180 ohm; on a clone it can hit 450 ohm worst-case. With 2 muxes in series that is up to 900 ohm of fixed series resistance in front of R_cell. Below ~5 kohm of pressure the reading collapses into the mux noise floor.

## 3. Gerber inspection (`gerbers.zip`)

_1 finding(s)._

### [MAJOR] `GBR-LAYER-EMPTY` — Outer copper layer `conet-scanner-v1-B_Cu.gbr` is essentially empty (364 B, 1 traces)

**Refs:** `conet-scanner-v1-B_Cu.gbr`

`conet-scanner-v1-B_Cu.gbr` is 364 bytes with **1** drawn copper segments. For a 4-layer board this means there is no return path / pour on this outer layer. Signal integrity for any trace that depends on this layer as its reference plane (and microstrip impedance control) is compromised.

If this is `B_Cu`, USB D+/D- and digital I/O on the top layer have no controlled-impedance return; USB 12 Mbps still works but EMI and ESD margins are reduced. Add a solid GND pour on B_Cu before final tape-out.


## 4. Power budget under Shenzhen reality

_1 finding(s)._

### [MAJOR] `PWR-LDO-BURST-TSD` — U5 burst die temp 174 C in WIFI_HOTPA exceeds thermal shutdown

**Refs:** `U5`

WiFi burst peak in scenario `WIFI_HOTPA` (WiFi peak with hot PA (degraded silicon)) would, on a worst-case clone LDO at 40.0 C ambient, push the die to **174 C**. Clone TLV1117LV33 substitutes (HT7333, TP1117) trigger thermal shutdown around 120-140 C. The first burst on a clone part may foldback for tens of ms causing a brief +3V3 sag.

Mitigation:
* Use larger copper pour around U5 tab (target RthJA <= 35 C/W).
* Or replace U5 with an AP2112K-3.3 (LDO with native foldback + better RthJA).
* Or push WiFi power down via `WiFi.setTxPower(WIFI_POWER_11dBm)` in firmware.


## 5. ESP32-S3 strapping / boot integrity

_3 finding(s)._

### [WARNING] `STRAP-ANTENNA-KEEPOUT` — WROOM-1 antenna keep-out (15 mm) not satisfiable on 60x40 board

**Refs:** `U1`

ESP32-S3-WROOM-1 datasheet requires 15 mm of antenna keep-out (no copper, no metal). With U1 placed at (30, 22) mm on a 60 x 40 mm board, the antenna extends past the board edge -- WiFi link budget is reduced by ~6 dB. Documented as a known issue in README.md; included here for completeness so field deployments default to wired Ethernet.

### [WARNING] `STRAP-PSRAM-VARIANT` — Firmware must be built for `N8R8` octal PSRAM variant specifically

**Refs:** `U1`

BOM specifies ESP32-S3-WROOM-1**-N8R8** (8 MB flash + 8 MB octal PSRAM). The firmware in `firmware/tactile_scanner_esp32` must be compiled with `CONFIG_SPIRAM_MODE_OCT=y` and `CONFIG_ESPTOOLPY_FLASHSIZE_8MB=y`. If a stock Arduino IDE board profile for 'ESP32-S3 DevKitC' is used, PSRAM stays in quad mode and accesses fail silently. The CI build script `firmware/.../wokwi/build_firmware.sh` needs auditing for the right platformio env.

### [INFO] `STRAP-INFO-GPIO48` — GPIO48 (red LED) sits at ~0 V during boot via 1k+LED

**Refs:** `U1.GPIO48`, `D3`, `R21`

GPIO48 is **not** a strapping pin on ESP32-S3 but it is left floating during the first ~300 ms of boot. The current schematic puts 1k -> red LED -> GND on this pin. During boot the pin floats high-Z; the LED is dark. After firmware takes over the pin is driven explicitly. No risk. **Just confirming we checked.**


## 6. ADC divider & measurement range

_2 finding(s)._

### [WARNING] `ADC-DYNAMIC-RANGE` — Real ADC dynamic range with MUX R_on reality is 2232 counts (12-bit) -- 2348 per schematic

**Refs:** `U2`, `U3`, `R30`

The schematic divider math is optimistic. Computed counts between un-pressed (R_cell=30 kohm) and fully pressed (R_cell=2 kohm):

* Schematic (R_mux=80 ohm):     low=1020 hi=3368 span=2348
* Genuine TI typ (R_mux=180):   low=1015 hi=3313 span=2298
* Genuine TI worst (R_mux=270): low=1010 hi=3266 span=2256
* Clone typ (R_mux=320):        low=1008 hi=3240 span=2232
* Clone worst (R_mux=450):      low=1001 hi=3174 span=2173

Numbers stay healthy (~2000 counts out of 4095) even on a clone, but the calibration is no longer linear in pressure -- a per-cell baseline subtraction remains mandatory. Reality model passes.

### [WARNING] `ADC-ADS-PGA-CAUTION` — ADS1115 path B requires PGA gain = 1 (FS = +/-4.096V)

**Refs:** `U4`, `SJ1`

When jumper SJ1 routes U2 SIG to ADS1115 AIN0, the input swings 0..3.3 V single-ended. The ADS PGA defaults to gain 2 (FS = +/-2.048 V) on hardware reset; that saturates at 2.048 V => values above ~62% of full pressure clip. Firmware must explicitly set PGA = 001 (FS = +/-4.096 V) before the first read. README claims `PGA up to +/-0.256 V` which is the opposite end of the gain table -- the README text is wrong and will mislead anyone bringing up path B.


## 7. Schematic vs Wokwi vs Firmware topology

_4 finding(s)._

### [MAJOR] `TOPO-WOKWI-MIRRORED` — Wokwi diagram and schematic disagree on which MUX feeds the ADC

**Refs:** `schematic.md`, `diagram.json`

Wokwi `diagram.json`:
* `row_mux:SIG` <-> `esp:3V3.1`      (row side = current source)
* `col_mux:SIG` <-> `esp:1`           (col side = ADC)
* `col_mux:SIG` <-> 10k <-> GND       (pull-down on col side)

Schematic prose:
* `U2 SIG` -> `ADC_IN` -> `GPIO 1`    (row side = ADC, per the netlist)
* `U3 SIG` -> R30 10k -> GND          (col side pulled down)

The two describe **mirror-image** circuits. The math (and the firmware) doesn't care which side is the source and which side is the ADC -- the divider produces the same V_ADC either way. But:

1. The PCB copper has to match *one* of them. If the layout follows the    schematic, the simulator is testing a circuit that doesn't exist on    silicon.
2. The firmware reads `GPIO 1 (ADC1_CH0) = ADC_IN`. In the schematic    wiring this is U2.SIG (row side); in the Wokwi wiring it is U3.SIG    (col side). The MUX row/col select code in `.ino` assumes the **row    side is the constant +3V3 source** (one MUX always drives, the other    always samples) -- this matches Wokwi, not schematic prose.

Conclusion: **the schematic prose is wrong; the Wokwi diagram is right**. Update `schematic.md` so the netlist matches the silicon. The PCB Gerbers should be re-inspected to confirm copper actually routes `+3V3` to `U2.SIG` and not the other way around.

### [MAJOR] `TOPO-WOKWI-BOARD-MISMATCH` — Wokwi board attrs do not match the WROOM-1-N8R8 part on the BOM

**Refs:** `diagram.json`, `U1`

`psramType` = `none`, but real module is WROOM-1-**N8R8** (8 MB octal PSRAM). Any firmware code that uses PSRAM (`ESP.getPsramSize() > 0`) passes the wokwi test silently and fails on silicon.

`flashSize` = `4` MB, but real module is **N8** (8 MB). Partition tables that overflow the simulator's 4 MB image will be silently truncated by wokwi and crash on silicon.

### [WARNING] `TOPO-FIRMWARE-INA826` — firmware comment claims INA826 differential amp; BOM does not include one

**Refs:** `tactile_scanner_esp32.ino`

`tactile_scanner_esp32.ino` top-of-file comment:

> ... samples one piezo-resistive cell at a time through an **INA826 differential amplifier** connected to ADC1.

The BOM has no INA826. The `analogRead(ADC_PIN)` in the actual loop reads the MUX SIG node directly with no front-end amplification.

Either:
* The comment is stale and should be removed -- silicon doesn't have   an INA826; the divider math runs unbuffered.
* Or path B (ADS1115) was supposed to be the differential path and the   INA826 mention is a leftover from an earlier revision.

Cosmetic but misleading; flag for whoever brings up the first article.

### [ADVISORY] `TOPO-WOKWI-CELL-COVERAGE` — Wokwi diagram only models 5 cells out of 256

**Refs:** `diagram.json`

The 16x16 mesh has 256 cells. The Wokwi diagram instantiates only **5** of them as wokwi-resistor parts. The remaining 251 cells appear as open circuits to the simulator. The scan loop will read those positions as 0 mV (good baseline) but the MUX cross-talk and leakage through unmodelled cells is invisible to the test. Test coverage is happy-path only.


## 8. Reality-adjusted software-mode simulation

_1 finding(s)._

### [WARNING] `SIM-FALSE-POSITIVE` — `no_press` matrix yielded 256 non-zero cells

**Refs:** `scanner_frame.h`

With every cell at the un-pressed value (~R_cell=30 kohm), the compressed payload should be near-zero everywhere. Seeing 256 non-zero cells means the noise floor / kAdcDead threshold (32 counts) is too low for the real divider output (~1000 counts with R_mux=320 ohm). The firmware will report phantom touches on an unloaded mesh. **Recommend raising kAdcDead to ~80 counts or adding a per-cell baseline.**
